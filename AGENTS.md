# Development

This is a Telegram join verification bot on Cloudflare Workers with no frontend.

- Edit strict TypeScript in src/. dist/ is generated and must never hold handwritten changes. Shared interfaces live in src/types.d.ts.
- Use Hono for the webhook, grammY (`Bot`, `Composer`, `Api`) for Telegram Bot API calls, update routing and Telegram types, and Drizzle with D1 for storage. Prefer an existing grammY feature or plugin over new hand-written Telegram plumbing; keep custom code for session CAS/leases, persistence and quiz/spam logic. Runtime code must use Workers APIs rather than Node.js filesystem or process APIs, so check that a plugin bundles for Workers before adopting it (`@grammyjs/i18n` does not: it pulls in Deno shims).
- All database calls are async. Persist answers with revision CAS and API decisions before sending. Do not assume a transaction spans D1 and Telegram.
- Authenticate webhook requests before parsing their bodies: check `X-Telegram-Bot-Api-Secret-Token` in our own Hono middleware before grammY's `webhookCallback`, which reads the body first and accepts every request when no secret is set. Await processing before acknowledging updates; return a retryable error on failed processing, so never swallow handler errors (webhook updates bypass `bot.catch`; the Hono handler logs the update ID and error code, then rethrows), never use `onTimeout: "return"`, and keep webhook replies disabled (`canUseWebhookReply: () => false`) because decisions must be persisted around the real API result. Overdue sessions, pending decisions and message deletion are handled by per-session Durable Object alarms (`SessionTimer`) that re-read D1 before acting; cron maintenance is the backstop. The timer only wakes the service, so never put state or decisions in the Durable Object, and never rename the class without a new `migrations` tag.
- Log Telegram failures by method name and error code only; never log tokens, grammY error payloads or `HttpError.error`. Retry only 429 inside a request (`@grammyjs/auto-retry` with `rethrowInternalServerErrors` and `rethrowHttpErrors`); every other ambiguous failure stays pending in D1.
- Keep prompts localized in en and cn. Question translations share an answer index and option count. Correct answers must never appear in public UI.
- Use oxlint and oxfmt. Run pnpm check before delivering changes.
- Tests run source using Vitest and real SQLite adapters; validate D1 SQL using local Wrangler migrations.
- .tgcloud/ is dead legacy private state; leave it alone. .dev.vars, .env files, .wrangler/ and private-content/ are private. Never commit tokens or question content.
- Spam blocklists are generated with `pnpm blocklist:build` from the upstream sources in blocklist/sources.json and the curation in blocklist/overrides.json. Pin source URLs to commits, and keep README › Blocklist sources listing every source with its URL, license and removal notice.
- Question packs live in D1 (`packs`, `rules`, `questions`) and are synced from the gitignored private-content/ checkout with `pnpm content:push|pull|list`; the Worker bundle never contains content, and deploy never writes D1.
- Deployment and D1 migrations are separate. Live Telegram checks need a dedicated test group; local mocks do not prove live Telegram behavior.
